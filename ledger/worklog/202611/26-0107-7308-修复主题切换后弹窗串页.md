## Process

- 纠正：先前判断只改 `src/app/current-page.ts` 就够，是错的。真机日志显示命令侧一直正确：`[mptk-debug:page-key]` 与 `[mptk-debug:command]` 都是 `mptk-page-2`；主题切换后 `[mptk-debug:kit-page]` 显示首页宿主的 pageKey 从 `mptk-page-1` 变成 `mptk-page-2`，`mptk-dialog-host-1` 因此抢走本属于 dialog 页宿主的弹窗。
- 真根因在 `src/app/KitPage.tsx`：每次渲染都重新 `pageKeyOf(Taro.getCurrentInstance().page)`；全局主题 store 更新时保留在页面栈里的首页页面树重渲染，Taro 当前实例是活跃 dialog 页，于是旧页宿主被改成活跃页身份。和命令侧取自哪里无关。
- 官方依据：Taro《 getCurrentPages 》明确数组最后一个是当前页，不要修改页面栈，不要在 `App.onLaunch` 调用；微信《 getCurrentPages 》同样定义最后一个是当前页，并说明 `navigateTo` 保留原页面；Taro《 getCurrentInstance 》只说明返回 `Current.page`，未定义它等于「正在重渲染的页面树自己的 page」。第三方《Taro 开发文档 - 开发规范、常见问题、性能优化》指出频繁调用 `getCurrentInstance()` 可能出问题，推荐组件内取一次保存。
- 身份修复：`src/app/KitPage.tsx` 用 `useRef` 在首次渲染固定 host 身份；`src/app/current-page.ts` 当前页身份只读页面栈顶，空栈返回空串；消费方 API 不变，不传 `pageKey`，不改主题流程，不清空弹窗。
- 动画修复：`src/ui/infra/DialogHost.tsx` 原来 `open` 恒 true、关闭即从 overlays 移除，PopUp 的 transition 没有起点也没有退场时间。现在退场载荷保留 `MOTION_DURATION`；`Popup` / `ContentPopup` 新增 `animateOnMount`，命令弹窗首帧挂载关闭态、下一帧展开；`usePresence` 支持 `initialOpen=false` 且首帧就挂载。
- 已补回归：`tests/app.test.mjs` 断言身份只读栈顶、空栈不猜、宿主身份首次渲染固定；`tests/render.test.mjs` 补主题更新归属与页面切换不改写归属；`tests/layout.test.mjs` 把 DialogHost 纳入 presence 回归。
- 验证：`pnpm run build`、`pnpm test` 242/242、`pnpm run guard`、`pnpm pack --dry-run`、`pnpm --filter mp-taro-kit-demo build:weapp`、codelint 13 文件六层全过；源码无 `mptk-debug` 残留。

## Conclusion

真因是宿主身份每次渲染重取，主题重渲染把旧页宿主改成活跃页身份；已改为首次渲染固定并保留命令侧栈顶单一真源。命令弹窗动画已接回 Popup 的进出场路径。自动化与门禁全过；真机验证仍待用户确认。
