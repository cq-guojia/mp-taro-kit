## Background

用户反馈：dialog 演示页切换明暗后，点页面按钮像没反应；退回首页，之前点的弹窗都弹在首页；关掉首页弹窗再进 dialog 页恢复正常。要求不要打补丁，按正规方案解决，且不能把问题留给消费方；本任务由用户明确要求建任务并认领。

## Process

- 现象链路：`demo/src/components/DemoSettings.tsx:81` → `src/runtime/theme.ts:115-117` 通知全局订阅者；`src/ui/infra/use-theme.ts:6-12` 与 `DialogHost.tsx:23` 让所有保留页（含首页）重渲染；`src/ui/commands.ts:212` 发起命令时调用 `currentPageKey()`；`src/app/current-page.ts:28` 优先取 `getCurrentInstance()?.page`，把首页实例当成发起页；`src/ui/infra/DialogHost.tsx:35-41` 只渲染 pageKey 匹配的载荷，于是 dialog 页没反应、首页弹窗出现。
- 根因是同一概念有两个真源：导航栈与执行上下文实例。主题重渲染只是触发事件，不是根因。
- 官方依据：Taro《 getCurrentPages 》明确数组最后一个是当前页，不要修改页面栈，不要在 `App.onLaunch` 调用；微信《 getCurrentPages 》同样定义最后一个是当前页，并说明 `navigateTo` 保留原页面；Taro《 getCurrentInstance 》只说明返回 `Current.page`，未定义它等于页面栈顶。第三方《Taro 开发文档 - 开发规范、常见问题、性能优化》指出频繁调用 `getCurrentInstance()` 可能出问题，推荐组件内取一次保存。
- 方案合理性：以官方文档定义的页面栈作为唯一真源，命令发起时盖一次 pageKey，消费方 API 不变，不新增 `pageKey` 参数，不改主题流程，不清空弹窗，不给 demo 加特判；属于治根因的结构修复，不是补丁。
- 消费方契约：用 `KitPage` 的页面零改动；手动挂 `DialogHost` 且不在 `KitPage` 下的既有契约仍只认领无页面身份的弹窗；页面栈为空时返回空串，按无身份处理，不抛错，也不要求消费方兜底。
- 未决：真机尚未打日志确认主题重渲染后 `getCurrentInstance().page` 的具体指向；本修复不依赖该细节，因为命令侧不再读它。仍需真机确认页面栈 page 对象与 `KitPage` 渲染时拿到的 page 对象是同一个。

- 已实现：`src/app/current-page.ts` 删除 `getCurrentInstance` 类型与读取，当前页身份只读 `Taro.getCurrentPages()` 栈顶，空栈返回空串。
- 已补回归：`tests/app.test.mjs` 用 TS 转译 + Taro 桩断言「栈顶 B、实例 A」时返回 B、空栈不猜页面；`tests/render.test.mjs` 补主题更新归属与页面切换不改写归属两条；`tests/ui.test.mjs` 原有宿主认领断言保持通过。
