## Background

触发来源：用户 2026-11-21 给的两张竞品图（`授权弹窗界面—UI分享`、`APP 底部弹窗 Screen`），指出基础弹窗已做出来，但业务里反复出现的多种弹窗形态需要提前抽象，让使用方少定义。

前因与已定调：

- 库内已有 `Popup`（五档位置 + `surface='panel' | 'none'` 裸壳，见 `src/ui/layout/Popup.tsx:40-82`）与 `ImagePopup`（配置式图片弹窗，底层是裸壳居中 Popup，见 `src/ui/layout/ImagePopup.tsx:40-63`、`docs/api/popup.md:117-143`）。
- 第一轮讨论结论：应该提供，但不往 `Popup` 上加 `title` / `footer` / `actions` 具名槽位；`Popup` 保持底座，在 `layout` 子域新建配置式高层弹窗，与 `ImagePopup` 同级、基于 `Popup`（含裸壳）实现。
- 用户 2026-11-21 确认：`ImagePopup` 就放在那，它就是存图片用的；新能力与它是同一层级的另一种应用，同样基于透明/基础 Popup 做扩展应用。
- 用户 2026-11-21 拍板：组件名就用 **`ContentPopup`**（看过 `NoticePopup` / `InfoPopup` / `Modal` 等候选后仍选回它）；形态只用一个 `variant` 旋钮，不拆成多个组件；`ImagePopup` 保持原样不动。
- 用户 2026-11-21 最终确认：三档 variant 定稿（删掉 `icon` 档）、`badge` 用 `badgeRadius` 取代形状枚举、新增描边两轴、位置只做 `center` / `bottom`；明确说「更新 Worklog，更新好了就开工」，授权进入实现。demo 展示由 agent 组织：接着 popup 页 ImagePopup 后面展示，一个类型一个 Cell，Cell 后跟几个按钮触发。

用户原话需求（逐条记录，不改写口径）：

1. **handle（头部/标题区）**：支持纯文字样式——一个标题、带一个小备注（副标题），前面或旁边配一个小 icon，整体像标题。
2. **顶部图片**：可放一张完整图片，位于整个浮窗最上面；图片可选择透明，因为有些地方是异形的，只要与背景同色（用户举例白色）就能和下面内容接上；中部弹窗与底部弹窗至少都要支持（顶部形态用户还没想清楚，待补案例）。
3. **按钮**：提供默认按钮形式——左右排、上下排；调用方觉得 footer 和 handle 已经够用就不必自己定义；真要完全自定义，才用纯透明的东西完全自己定义 view。
4. **半幅徽标**（来自老项目、现在还没搬）：外伸出面板的容器，可以是圆或其他形状；里面放 icon，容器可设纯色/渐变背景；下面可带标题、也可没有。形状与大小可设，位置可居中/偏左/偏右，浮出量可按比例（如 40%）设置，还要有描边。
5. **总目标**：以后可以提供很多种弹窗样式，尽量让用户少去定义；只要不违反整个框架就应该提供。
6. **本轮明确指令**：建任务并把前因后果与需求全写进 work log；调研别人用什么方式提供这类能力；结合老项目需求与本次需求给完整方案，包括参考成熟项目怎么运营、提供哪些槽位。
7. **最终指令**：更新 Worklog，更新好了就开工；demo 接着 popup 页展示，三类型各一个 Cell + Cell 后跟按钮。
