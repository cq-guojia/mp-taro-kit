## Background

触发来源：用户 2026-11-21 给的两张竞品图（`授权弹窗界面—UI分享`、`APP 底部弹窗 Screen`），指出基础弹窗已做出来，但业务里反复出现的多种弹窗形态需要提前抽象，让使用方少定义。

前因与已定调：

- 库内已有 `Popup`（五档位置 + `surface='panel' | 'none'` 裸壳，见 `src/ui/layout/Popup.tsx:40-82`）与 `ImagePopup`（配置式图片弹窗，底层是裸壳居中 Popup，见 `src/ui/layout/ImagePopup.tsx:40-63`、`docs/api/popup.md:117-143`）。
- 第一轮讨论结论：应该提供，但不往 `Popup` 上加 `title` / `footer` / `actions` 具名槽位；`Popup` 保持底座，在 `layout` 子域新建配置式高层弹窗，与 `ImagePopup` 同级、基于 `Popup`（含裸壳）实现。
- 用户 2026-11-21 确认：`ImagePopup` 就放在那，它就是存图片用的；新能力与它是同一层级的另一种应用，同样基于透明/基础 Popup 做扩展应用。
- 用户 2026-11-21 拍板：组件名就用 **`ContentPopup`**（看过 `NoticePopup` / `InfoPopup` / `Modal` 等候选后仍选回它）；形态只用一个 `variant` 旋钮，不拆成多个组件；`ImagePopup` 保持原样不动。

用户原话需求（逐条记录，不改写口径）：

1. **handle（头部/标题区）**：支持纯文字样式——一个标题、带一个小备注（副标题），前面或旁边配一个小 icon，整体像标题。
2. **顶部图片**：可放一张完整图片，位于整个浮窗最上面；图片可选择透明，因为有些地方是异形的，只要与背景同色（用户举例白色）就能和下面内容接上；中部弹窗与底部弹窗至少都要支持（顶部形态用户还没想清楚，待补案例）。
3. **按钮**：提供默认按钮形式——左右排、上下排；调用方觉得 footer 和 handle 已经够用就不必自己定义；真要完全自定义，才用纯透明的东西完全自己定义 view。
4. **第三种样式**（来自老项目、现在还没搬）：图标飘在中间一个大圆里，有一半浮出去。
5. **总目标**：以后可以提供很多种弹窗样式，尽量让用户少去定义；只要不违反整个框架就应该提供。
6. **本轮明确指令**：建任务并把前因后果与需求全写进 work log；调研别人用什么方式提供这类能力；结合老项目需求与本次需求给完整方案，包括参考成熟项目怎么运营、提供哪些槽位。

## Process

代码现状（已核对，非推测）：

- `src/ui/layout/Popup.tsx:40-82`：`PopupProps` 只有 `children`，没有具名槽位；`surface='none'` 是裸壳扩展点，`panelStyle` 让面板贴合内容。
- `src/ui/layout/ImagePopup.tsx:16-46`：按钮是配置式 `actions`（文字按钮 `{text} + ButtonProps` / 图片按钮 `{src}`），`actionsAlign` 只有 `center | left | right` 一轴（横向对齐），没有上下排。
- `src/ui/layout/close-position.ts:2,27-48`：五档位置与关闭按钮位置表；`top` 档关闭按钮只能落面板下方。
- `docs/api/popup.md:17,50-65`：面板高度纯由 children 撑开、不写 `max-height`；裸壳与面板高度模型一致。
- `docs/api/overlay.md:92-97`：不做 `rootPortal` / 镂空 / 暴露 `zIndex` / 声明式入栈。

成熟项目调研（本轮）：

- NutUI（官方 `https://nutui-uniapp.netlify.app/components/feedback/dialog`，v1.11.2）：`title` / `content` 配置 + `header` / `default` / `footer` 三个槽位；按钮排布是独立 prop `footer-direction: horizontal | vertical`（默认 horizontal）；`no-footer` / `no-ok-btn` / `no-cancel-btn` 分别控制按钮栏与单个按钮。
- TDesign 小程序（官方文档搜索结果与官方仓库示例）：Dialog 用 `actions`（数组，元素为 Button API）+ `button-layout: horizontal | virtual/vertical`（uni-app 侧为 `horizontal | vertical`，默认 horizontal）；槽位有 `top` / `title` / `content` / `middle` / `actions` / `cancel-btn` / `confirm-btn`；提供「带图片对话框」示例，说明图片头属于对话框的一种配置形态，不是另一个组件。
- Vant Weapp：Dialog 走 `title` + `message` + 确认/取消配置（含函数式 `Dialog.alert` / `Dialog.confirm`）；Popup 是裸容器，标题与底部按钮靠调用方在 slot 里组合，Vant 4 侧另有 `header` 槽位可做自定义标题栏。
- antd-mobile：`Dialog` 是配置式确认框，`Popup` 是定位容器，二者分层，与「底座 + 特化」的分工一致。

共同规律：成熟库把「头部 / 内容 / 底部按钮」做成槽位 + 配置双通道，按钮横纵排布做成独立轴；图片头是对话框的一种形态，不另起一套弹窗体系。

关键约束与坑（写入方案时不能丢）：

- 用户说的「图片做成白色和背景接上」不能写死白色：库有明暗主题，透明异形图必须配一个随面板 surface 走的 token 才能在两套主题下都接得上。
- 半浮出去的徽标不能用负 margin / `gap`：Skyline 不支持（见 `docs/api/overlay.md:101`、`docs/api/compiler-toolchain.md` 相关条目），要用 `position: absolute` + `transform` 位移，与 Popup 外置关闭叉同口径。
- 徽标与 `closePosition` 有碰撞风险，需给出互斥或避让规则。
- 保留 `children` 覆盖口，完全自定义走现有 `surface='none'`，不新造「透明模式」。

用户追加的头部场景与对应参数设计（2026-11-21 本轮）：

- 头部形态扩为四档 `variant: 'title' | 'icon' | 'image' | 'badge'`：`title`=纯标题（可带小 icon 与副标题）；`icon`=圆/圆角容器内的大图标，容器可纯色或渐变背景，标题可有可无；`image`=图片头，默认透明无背景、可传背景；`badge`=老项目形态，图标半浮出面板上沿。
- 背景分三作用域：`panelBackground`（整面板 / 内容区，支持渐变铺满）、`headerBackground`（头部区，图片头默认透明）、`iconBackground`（图标容器，纯色或渐变）。值为颜色字符串或 `{ from, to, direction? }`，走内联 style，不在组件里写死色值。
- `headerDivider` 控制头部与内容之间是否画分割线；默认按 variant 给推荐值（title/icon 开、image/badge 关），可显式覆盖。
- footer 三种覆盖层级：配置式 `actions` + `actionsLayout('row' | 'column')` + `actionsAlign`；只覆盖 `footer` 槽位；或只传 `children` + `surface='none'` 全自绘（此时头/尾配置块不渲染）。优先级统一为「槽位 > 配置 > 默认」。
