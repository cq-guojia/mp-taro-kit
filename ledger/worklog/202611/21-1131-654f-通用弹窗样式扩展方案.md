## Background

触发来源：用户 2026-11-21 给的两张竞品图（`授权弹窗界面—UI分享`、`APP 底部弹窗 Screen`），指出基础弹窗已做出来，但业务里反复出现的多种弹窗形态需要提前抽象，让使用方少定义。

前因与已定调：

- 库内已有 `Popup`（五档位置 + `surface='panel' | 'none'` 裸壳，见 `src/ui/layout/Popup.tsx:40-82`）与 `ImagePopup`（配置式图片弹窗，底层是裸壳居中 Popup，见 `src/ui/layout/ImagePopup.tsx:40-63`、`docs/api/popup.md:117-143`）。
- 第一轮讨论结论：应该提供，但不往 `Popup` 上加 `title` / `footer` / `actions` 具名槽位；`Popup` 保持底座，在 `layout` 子域新建配置式高层弹窗，与 `ImagePopup` 同级、基于 `Popup`（含裸壳）实现。
- 用户 2026-11-21 确认：`ImagePopup` 就放在那，它就是存图片用的；新能力与它是同一层级的另一种应用，同样基于透明/基础 Popup 做扩展应用。
- 用户 2026-11-21 拍板：组件名就用 **`ContentPopup`**（看过 `NoticePopup` / `InfoPopup` / `Modal` 等候选后仍选回它）；形态只用一个 `variant` 旋钮，不拆成多个组件；`ImagePopup` 保持原样不动。
- 用户 2026-11-21 最终确认：三档 variant 定稿（删掉 `icon` 档）、`badge` 用 `badgeRadius` 取代形状枚举、新增描边两轴、位置只做 `center` / `bottom`；明确说「更新 Worklog，更新好了就开工」，授权进入实现。demo 展示由 agent 组织：接着 popup 页 ImagePopup 后面展示，一个类型一个 Cell，Cell 后跟几个按钮触发。

用户原话需求（逐条记录，不改写口径）：

1. **handle（头部/标题区）**：支持纯文字样式——一个标题、带一个小备注（副标题），前面或旁边配一个小 icon，整体像标题。
2. **顶部图片**：可放一张完整图片，位于整个浮窗最上面；图片可选择透明，因为有些地方是异形的，只要与背景同色（用户举例白色）就能和下面内容接上；中部弹窗与底部弹窗至少都要支持（顶部形态用户还没想清楚，待补案例）。
3. **按钮**：提供默认按钮形式——左右排、上下排；调用方觉得 footer 和 handle 已经够用就不必自己定义；真要完全自定义，才用纯透明的东西完全自己定义 view。
4. **半幅徽标**（来自老项目、现在还没搬）：外伸出面板的容器，可以是圆或其他形状；里面放 icon，容器可设纯色/渐变背景；下面可带标题、也可没有。形状与大小可设，位置可居中/偏左/偏右，浮出量可按比例（如 40%）设置，还要有描边。
5. **总目标**：以后可以提供很多种弹窗样式，尽量让用户少去定义；只要不违反整个框架就应该提供。
6. **本轮明确指令**：建任务并把前因后果与需求全写进 work log；调研别人用什么方式提供这类能力；结合老项目需求与本次需求给完整方案，包括参考成熟项目怎么运营、提供哪些槽位。
7. **最终指令**：更新 Worklog，更新好了就开工；demo 接着 popup 页展示，三类型各一个 Cell + Cell 后跟按钮。

## Process

代码现状（已核对，非推测）：

- `src/ui/layout/Popup.tsx:40-82`：`PopupProps` 只有 `children`，没有具名槽位；`surface='none'` 是裸壳扩展点，`panelStyle` 让面板贴合内容。
- `src/ui/layout/ImagePopup.tsx:16-46`：按钮是配置式 `actions`（文字按钮 `{text} + ButtonProps` / 图片按钮 `{src}`），`actionsAlign` 只有 `center | left | right` 一轴，没有上下排。
- `src/ui/layout/close-position.ts:2,27-48`：五档位置与关闭按钮位置表；`top` 档关闭按钮只能落面板下方。
- `docs/api/popup.md:17,50-65`：面板高度纯由 children 撑开、不写 `max-height`；裸壳与面板高度模型一致。
- `docs/api/overlay.md:92-97`：不做 `rootPortal` / 镂空 / 暴露 `zIndex` / 声明式入栈。

成熟项目调研（本轮）：

- NutUI（官方 v1.11.2）：`title` / `content` 配置 + `header` / `default` / `footer` 槽位；`footer-direction: horizontal | vertical` 控按钮横纵；`no-footer` / `no-ok-btn` / `no-cancel-btn` 控按钮栏。
- TDesign 小程序：Dialog 用 `actions` 数组 + `button-layout: horizontal | vertical`；槽位 `top` / `title` / `content` / `middle` / `actions` 等；官方有「带图片对话框」示例，图片头归 Dialog 的一种形态。
- Vant Weapp：`Dialog` 是标题+消息+按钮的告知确认框，`Popup` 是裸容器，标题与底部靠 slot 组合。
- antd-mobile：`Dialog` 配置式确认框、`Popup` 定位容器，分层与本库一致。

共同规律：成熟库用「头部 / 内容 / 底部」槽位 + 配置双通道，按钮横纵排布独立成轴，图片头是对话框的一种形态而非独立品类。

关键约束与坑：

- 「图片做成白色和背景接上」不能写死白色：库有明暗主题，透明异形图必须配随面板 surface 走的 token。
- 徽标浮出不能用负 margin / `gap`：Skyline 不支持，用 `position: absolute` + `transform: translateY(-<overlap>)`（百分比按容器自身算），复用 Popup 外置关闭叉的 overflow 处理方式。
- 徽标与 `closePosition` 冲突时徽标优先，面板内 `top-*` 档回落到外置档。
- 完全自定义走现有 `surface='none'`，不新造「透明模式」。

最终对外契约（用户拍板后定稿）：

- `variant: 'title' | 'image' | 'badge'`；`position: 'center' | 'bottom'`（类型层限制，运行时越界回落 `'center'`；不做 top / 左右）。
- 三档头部：`title` = 小 `icon`/`glyph` + `title` + `subtitle` 三件一体、小图标无背景不可设形状；`image` = `image`（复用 `ImageSizeInput`）+ `headerBackground`（默认透明）；`badge` = 外伸容器 + `badgeIcon`/`badgeGlyph` + 可选 `title`。
- 背景三作用域：`panelBackground`（整面板/内容区，可渐变铺满）、`headerBackground`（头部区）、`badgeBackground`（徽标容器），值 = 颜色字符串或 `{ from, to, direction? }`，走内联 style。
- `headerDivider`：头部与内容间分割线，按 variant 给推荐默认（title 开、image/badge 关），可覆盖。
- footer 三层级：配置 `actions` + `actionsLayout('row' | 'column')` + `actionsAlign`；只覆盖 `footer` 槽位；或只传 `children` + `surface='none'` 全自绘。优先级「槽位 > 配置 > 默认」。
- badge 专属：`badgeRadius`（`'none' | 'sm' | 'md' | 'lg' | 'circle' | number | string`，circle = 50%）、`badgeSize`、`badgeAlign`（`center | left | right`）、`badgeOffset`（number px / `'20%'` 面板宽）、`badgeOverlap`（number px / `'40%'` 容器自身高，默认 50%）、`badgeBorderWidth`（token 默认 2）、`badgeBorderColor`（token 默认面板 surface 色）、`badgeBackground`。没传图标就不渲染空容器。

四角色评审的处置（已并入方案）：

- 产品：按钮 0~3、纵排顺序按数组；长文案行数与省略由设计给值；不做输入/表单/曝光回调/页面回退关闭，内容由 children 承载。
- 项目：范围边界写进「不做什么」；交付物含源码/出口/样式/docs/demo/tests/token/更新日志；按固定门禁顺序验证；新 token 必须有默认值，不影响现有组件；发版仍由 `v*` tag 触发，不 bump 不打 tag。
- 设计：所有新增色走明暗 token；尺寸吃全库刻度；badge 外伸不被裁且与关闭叉不叠；跟着面板一起进出；空图标不渲染容器；暗色渐变与描边过对比度基线。
- 架构：基于 Popup 不复制遮罩/层级/安全区；只依赖 layout 内部 + Button + CloseGlyph + image-size + runtime 安全区；导出 Props/Variant/BackgroundValue/Action 类型；参数正交、槽位只做逃生舱；Skyline 禁负 margin/gap/通配符/calc 乘法；测试覆盖三形态、按钮两轴、背景三作用域、槽位优先级、位置限制、关闭叉避让、token 存在。

Demo 组织（用户授权 agent 决定）：接着 `demo/src/pages/popup/index.tsx` 的 ImagePopup 展示块之后加一块，沿用 `DemoBlock` 外层 Card；内部 `CellGroup` 三个 Cell 对应 title / image / badge 三档，每个 Cell 的 `value` 用 `View` 包几个 xs `Button` 触发对应形态；受控弹窗实例放组外，沿用 ImagePopup 现有写法；`catalog.ts` 的 popup 页 `examples` 加一条，`menuGroups` 已有 popup 条目不重复加。
