## Process

### 2026-11-25 架构 + 前端评审

**结论**：方案合理、无概念硬伤。命令是纯函数（`commands.ts:50,77,114,122`），宿主经 effect 注册（`ToastHost.tsx:19-22`），按需配置可行。问题全在打包边界。

**破坏按需的断点**：`create-kit-app.tsx:7-9,106` 静态引三宿主且默认全挂；`app/index.ts:3` 顶层 CSS；`ui/layout/index.ts:2-59` 大 barrel；`package.json:62-66` 仅通配一层且目标 `dist/ui/*/index.*`；`ui/index.ts:3-8` 暴露内部状态与 mark 函数（shim 已删，mark 系列仍暴露）。

**迁移顺序**：先补显式子路径并保留旧出口 re-export → 拆 commands、旧 `ui` 出口暂作 facade → CSS 移到组件/style 入口 → 大版本再收窄出口。`hosts` 目标 `undefined = []`，三件旧默认只放 deprecated 兼容入口；不做 registry 隐式注册。

**Tree-shaking**：Vite（`demo/config/index.js:40`）+ ESM / `sideEffects` CSS（`package.json:18-20`）可摇纯导出，CJS 不摇（`docs/api/exports.md:43`）。`markCardEdgeOutOfFlow`（`card-edge.ts:46-48`，调用如 `FloatingAction.tsx:55`）是顶层副作用，触及即整模块保留。`hosts` 传参只管运行时挂载，与打包无关——要真排除代码必须不 import。

**CSS**：`app/index.ts:3` 的 floating-action CSS 移到 `KitPage.tsx`；但 `app/index.ts:6` 仍 re-export KitPage，单 `./app` 还会带入，须另开 `./app/kit-page` 才能 createKitApp-only 不带，KitPage 出口仍自带样式。

**验收**：真实 Taro/Vite 双探针看产物——只引 toast 时无 `DialogHost` / `showLoading` / `alert` / `mptk-fab-group`，引 KitPage 才有 `mptk-fab-group--bottom-right`；再断言 dist 三件套、`import.meta.resolve`、宿主缺失运行时抛错，不靠源码字符串。

**不做**：globalThis、enableXxx、默认全挂、直接删旧路径、根出口继续导出 `uiState` / mark。
