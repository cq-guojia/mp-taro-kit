- 2026-11-14 外部核实：W3C DTCG Format Module 2025.10 的三层 taxonomy 为 primitive → semantic → component（Material 3 称 reference/system/component、Adobe Spectrum 称 global/alias/component、SLDS 称 primitives/aliases/styling hooks），「换肤只换语义层、primitive 不动」是标准做法；SLDS 2 直接暴露 `--slds-g-*` styling hooks 给宿主覆盖，不改组件内部类（sujeet.pro/articles/design-tokens-and-theming）。Bootstrap 5.3《Sass · Variable defaults》原文要求「Copy and paste variables as needed, modify their values… If a variable has already been assigned, then it won't be re-assigned by the default values」；shadcn/ui《Theming》给整份默认 scaffold 让宿主复制进 `app/globals.css`；Vant Weapp《定制主题》用同名 CSS 变量、`page { … }` 全局覆盖与 `var(--x, @default)` 回落。
- 2026-11-14 层叠顺序风险：主题出口 `src/design/theme-runtime.scss:7` 与 `src/design/theme-light.scss:4` 都是 `page { @include t.base; @include t.light; }`。新风格文件若也写 `page { --mptk-*: … }` 则同特异性，胜负由宿主引入顺序决定（demo 现由 `demo/src/app.scss:5` 的 `@use './app-theme'` 决定），属易错的隐性契约。

### 编译时机与顺序

- 挂在宿主构建**之前**：`demo/package.json:5-8` 的 `build:weapp` / `dev:weapp` 显式串成 `pnpm gen:config && taro build --type weapp`。不依赖 `pre*` 钩子——pnpm（本项目锁 12.3.4）默认不启用 pre/post 脚本。
- 生成器必须早于 Sass 编译：`demo/src/app.scss:5` 的 `@use './app-theme'` 在编译期就读取文件，晚一步会拿旧值。
- `dev:weapp --watch` 只在启动时生成一次；watch 期间改 `kit.config.ts` 需重启（或后续给生成器加 watch）。
- 生成物入库（照 `scripts/icons.mjs`），并加 `gen:config --check` 断言「生成物与源一致」，防手改。
- 生成期校验：键名 / 类型 / 值域（如 `toast.duration > 0`）、明暗两套齐全、`theme.surfaceBase` 与 `theme.json` 及 `dist/styles/theme-*.css` 同值（复用 `tests/theme.test.mjs:69-81` 的现成断言）。

### 消费方能配什么、应该配什么

| 块 | 可配（公开面） |
|---|---|
| `theme` | 品牌色 `business` / success / warning / danger；页面底色明暗两套；卡片面 / 描边 / 圆角；文字与边框层级色；控件圆角；控件默认尺寸档 |
| `ui` | Toast 默认时长与最多条数、Loading 默认遮罩、Overlay 行为 |
| `core` | `baseURL` / `timeout` / `storagePrefix` / `debug` / `headers`（收编 `src/core/configure.ts:4-10` 原有五项） |

一次换肤通常只配 5~8 项：`business`、`surfaceBase` 明暗、`cardRadius`、`toast.duration`、`core.baseURL` / `timeout`；其余吃库默认。

**不该配**（内部，配了会坏）：色板八支 × 四档、`gray-1~8`、字号 / 行高 / 间距 / 圆角原子档位（`docs/architecture/design-foundation.md:79/85`）、`control-thumb*` 恒白恒深（对比度硬约束 `src/design/_tokens.scss:202/316`）、图标包前缀、动效时长。逐实例差异一律走 props。判据：**无状态的全局默认才进配置；删掉配置文件能完整回默认**。

### 成熟项目依据

一份配置放项目根 + `defineConfig` 给类型：Vite `vite.config.ts`、Tailwind `tailwind.config.*`、Taro `config/index.js`、shadcn `components.json`。构建前跑生成器产出多类文件：Style Dictionary 官方《Formats》的 `source → platforms → files`（CSS 变量 / JS / 自定义 format / `outputReferences` 保留别名链），本库 `scripts/icons.mjs` 同构。运行时行为默认值走注入而非编进库产物：Vant `Toast.setDefaultOptions({ duration })` / `resetDefaultOptions()`、Ant Design `ConfigProvider`（官方警告 `message.xxx` 等静态方法拿不到 context；本库 `showToast()` 是命令式，用 `runtime/singleton` 跨副本单例绕开）。`package.json:7-10` 发布的是编译好的 dist 且一个包供多个企业项目复用，所以配置**不能**编进库产物。

### 验收判据

改 `toast.duration` 一处 → 所有 `showToast()` 生效且单次传值可覆盖；删掉 `kit.config.ts` → 全站回库默认、不抛错；配置写错 → 构建期报错并给修复动作；改 `theme.cardRadius` → `pnpm gen:config && pnpm build:weapp` 后配置页自动变 `xl（20px）`；手改配置页数值 → 测试红；主包 / 分包读同一份配置。

## Conclusion

- 总配置仍是 `src/design/_tokens.scss` 一份，站点通过覆盖同名 CSS 变量定制；明色页面底色改为浅灰，暗色保持深灰。
- 「主题配置」演示页已上线为基础规范首条：像设置列表一样逐项列默认值（颜色左明右暗），末尾附覆盖写法。暂不做交互，先把现有项列全。
- 运行时出口新增 `.mptk-light`，可在同一屏把子树强制回明色，与 `.mptk-dark` 对称。
- 控件默认尺寸有唯一真源 `CONTROL_SIZE_DEFAULT`（`mp-taro-kit/design` 导出），未来输入类控件直接引用。
- 本轮结论：用户提的三层读取成立，且就是 design token 分层的标准形态；本库已有 primitive（色板 / 档位）+ semantic（`--mptk-business`、`--mptk-card-radius` 等快捷键）两层雏形与宿主覆盖层，缺的是把语义层抽成独立可复制文件，以及配置页读合并数据。
- 可行性：**能干**。库侧新增 `src/design/theme-config.scss` + `./styles/theme-config` 出口，编译与校验已有自动钩子；配置页改编译期合并。两条硬约束：风格文件只写 `var(--mptk-*)` 别名或注释、不写字面值，否则重演圆角漂移；风格文件与主题出口的层叠顺序必须锁在库内，不能交给宿主排引入顺序。明暗两套需分别合并，`var()` 别名链要解析到字面量。
- 不建议现在加 DTCG 的 component token 层：该层只在多品牌 / 白标时才需要，本库的第三层应是宿主覆盖层，不是组件层。本轮只更新过程文档，未落码、未提交。
- 本轮定稿：配置不再只管样式，改为项目根一份 `kit.config.ts`（theme + ui + core），库侧给 `defineConfig` / 默认值 / 校验 / 生成器，构建前生成宿主侧三个产物，运行时由 `configure()` 注入行为默认值；demo 是第一个消费方，其他项目照抄同一套。配置不编进库 dist（单包多项目复用），生成物入库并加一致性断言。完整方案见上节。
