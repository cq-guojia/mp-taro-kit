库开发态：`DEFAULT_KIT_CONFIG` → `pnpm build` 前置 `gen:config --lib` → `_tokens.scss` mixin 体 + `src/design/kit-config.generated.ts` → `dist/styles/theme-*.css` + `dist/config/cli.mjs`；这一段在库发布前跑完，消费方完全无感。宿主构建态：`dist` 默认表 ⊕ `demo/kit.config.mjs` → **Taro 构建插件自动调用** `generate(defaults, overrides)` 纯函数 → `demo/src/app-theme.scss` / `theme.json` / `kit-config.generated.ts` → 同一次 `taro build` 的 Sass / TS 编译读取；消费方不敲任何命令。`--check` 必须是「独立重算期望 + 结构化比对 + 输入指纹（默认表 / 宿主配置 / 生成器脚本的 sha256）+ 变异测试（改一个键应只 diff 目标键）」，不能是重跑生成器再字符串自比（恒绿）；`--check` 不写盘，只挂库侧 `scripts/check.mjs` 与 CI，不是消费方操作。CI 另需 PR workflow（现 `.github/workflows/publish.yml` 仅 tag 触发、`:25` 无 gen 步骤）。

### 编译时机与顺序

- 挂在宿主构建**之前**：`demo/package.json:5-8` 的 `build:weapp` / `dev:weapp` 显式串成 `pnpm gen:config && taro build --type weapp`。不依赖 `pre*` 钩子——pnpm（本项目锁 12.3.4）默认不启用 pre/post 脚本。
- 生成器必须早于 Sass 编译：`demo/src/app.scss:5` 的 `@use './app-theme'` 在编译期就读取文件，晚一步会拿旧值。
- `dev:weapp --watch` 只在启动时生成一次；watch 期间改 `kit.config.ts` 需重启（或后续给生成器加 watch）。
- 生成物入库（照 `scripts/icons.mjs`），并加 `gen:config --check` 断言「生成物与源一致」，防手改。

### 成熟项目依据
