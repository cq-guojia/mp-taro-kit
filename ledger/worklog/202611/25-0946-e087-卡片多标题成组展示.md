## Background

### 需求原话与触发场景

2026-11-25 在对话框演示页（`demo/src/pages/dialog/index.tsx`）连续调整期间，用户提出一个**独立的新需求**，原话：

> "card 有很多种标题样式，我希望它能连起来一组，用一个 graph 作为外框，里面包含很多种标志和内容。"

逐轮关键原话（按时间顺序，便于新会话还原意图）：

1. "我问你就是一个 card。支不支持多个标题。我想把提示确认 confirm、自定义按钮、异步闸门放到一个卡里面，让它们连起来，样式还是保持一个样式。你试试放进去看看，我看看效果呢。"
2. "你告诉我他能支持吗？这个是 card 传进去的吗？不对呀，card 是怎么传进去的？是通过接口传进去的吗？我不确定啊，这种东西有可能支持吗？如果需要他支持，怎么做？比如说做个 cardgroup 可能吗？"
3. 我答"Card 只有一组 `title/subtitle`，用 `CellGroup` 在 children 里分组"之后，用户定性："**你不支持，你改个屁呀**"——明确否定用 `CellGroup` 冒充 Card 的多标题能力。
4. "你先给我改回来。建一个做 cardgroup 的任务。**先不定方向**，把前因后果给我说明白。"

用户随后说"写清楚后，我会开新的会话去做那个任务"——**本过程文档就是交接件**，必须自包含，不能依赖本次会话的聊天上下文。

- **先不定方向**：方案（CardGroup / Card 加 sections / 其它）不许预先选定；先把前因后果与歧义写清楚。

### 定稿方向（2026-11-25，用户已接受）

用户在本会话逐轮否定多种中间方案后，接受以下形态：

- **控件只有两个**：`Card`（唯一外框）+ `CardHead`（段头）。`CardTitle` / `CardSubtitle` / `CardGroup` 都不新增。
- 写法：`<Card><CardHead>标题 View…</CardHead>内容<CardHead>…</CardHead>内容</Card>`；标题是宿主自己写的 `View`，挂 `mptk-card__title` / `mptk-card__subtitle` 类名对齐字号与颜色档位，想塞 `Icon` 或改 `className` 都行。
- `CardHead` 根节点用**独立类名** `mptk-card-head`，只管留白与段间线；**不复用** `mptk-card__header`——`card/style/index.scss:110` 的 `.mptk-card--header-divider .mptk-card__header` 与 `:142` 的 `.mptk-card--edge-content .mptk-card__header` 是后代选择器，复用会让 body 里每个段头被画底线、清边距。
- 段间线交给 Card 现有 `edge.ts` decorator：连续的贴边段头拿 `{top:false,bottom:true}`（末段 `{false,false}`），底线归前一段画，视觉上首段上无线、末段下无线、中间接缝恰好一条；不新增线规则、不改 `edge.ts`。
- 不使用 CSS 结构伪类（WXSS 不认 `:first-child` / `:has()`），不使用 `sections` 数组参数（用户原话否定“把 HTML 写到参数里”）。
- 引用成本恒定 1 条 JS + 1 条 style：`CardHead` 与 `Card` 同在 `mp-taro-kit/ui/card` 单元导出，不新增细路径出口；`ui/` 顶层不 re-export。
- 成熟库核对结论：antd-mobile / TDesign / Vant 用“一个组件 + ReactNode 槽位”，shadcn 用逐层子标签（Web 单 barrel、源码可改）；**没有**成熟库要求 `CardHead > CardTitle + CardSubtitle` 三层。

2026-11-25 演示页调整中，我把四个示例合并为一个 `actions` 块，用四个 `CellGroup` 各带标题装进同一张 Card（`CellGroup.tsx:71-74` 有 title 渲染）。用户的定性是"你不支持，你改个屁呀"——这只是**消费方绕路**：Card 仍然只有一组标题，组内标题来自另一个组件。用户要的是 Card 体系本身具备"一组多标题 + 共享外框"的能力。

教训：这类需求先确认"能力落在哪一层"，别在演示页用现成组件拼一个看起来像的东西交差。

### 方案收敛过程（2026-11-25 多轮讨论）

用户逐轮否定了这些中间方案，定稿时**不要再提**：

| 被否方案 | 否定理由 / 证据 |
|---|---|
| 四个 `CellGroup` 塞进一个 `Card` | 标题来自 CellGroup，不是 Card 体系能力；用户定性“你不支持，你改个屁呀” |
| `CardGroup` + `sections` 数组（`content: <Button>`） | 用户：“我把 HTML 都写到一个参数里面去传，你自己觉得靠谱吗”——内容必须是 children，不是数据数组 |
| `CardGroup` 内再嵌 `Card` + section 复用 `mptk-card__header` | 前端评审：`flattenLeaves` 把 marked 节点当叶子（`edge.ts:96`），整组只拿一组提示；内层 Card 会重跑 decorator 覆盖外层提示（`Card.tsx:86`）；`.mptk-card--header-divider .mptk-card__header`（`style/index.scss:110`）与 `.mptk-card--edge-content .mptk-card__header`（`:142`）是后代选择器，会污染每段 |
| `CardHead` + `CardTitle` / `CardSubtitle` 三层子标签 | 用户：“定义了 N 多个控件”“每个都得引入才能用？”；前端评审：本库契约“引用单元是组件”（`docs/api/exports.md:33`），四个细路径 = 4 JS + 4 style；shadcn 多子组件是 Web barrel 产物，`docs/api/card.md:19` 已写明本库不取 |
| 标题全塞 `title` props | 用户：“隐藏了之后想加字体图标进去还能控制吗”——标题必须是可组合 children |
| CSS `:first-child` 自动认领第一个子元素 | WXSS/Skyline 不支持结构伪类（`docs/api/card.md:137`、全仓零命中）；`{list.map(...)}` / 条件渲染会让位置判定错位（`tests/card.test.mjs:391-419`） |

前端评审对成熟库的核验：antd-mobile / TDesign / Vant 是“一个组件 + ReactNode 槽位”，shadcn 是 Web 上逐层 `CardHeader > CardTitle`；**没有任何库要求 `CardHead > CardTitle + CardSubtitle` 三层**。用户接受“只留 CardHead 一层 + children 自己写 View 挂类名”的收敛形态。
