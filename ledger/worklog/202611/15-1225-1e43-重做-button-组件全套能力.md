**定稿契约（2026-11-15 用户拍板后）**

- 轴：`type`(default/primary/success/warning/danger) × `variant`(solid/soft/outline/ghost) × `size`(xs..xl) × `radius`(xs..pill)；`color` 任意品牌色覆盖 `type`；`icon`/`iconAfter`；`block`；无 children + icon ⇒ 正方形纯图标（不做 IconButton）。
- `color` 派生：solid 底色=color、字色按相对亮度选 `--mptk-surface-1` / `--mptk-fg`；soft 底色=`rgba(r,g,b, tint)`、边与字=color；outline 白底 + color 边字；ghost 只 color 字。`rgba()` 的 alpha 用变量 `--mptk-c-btn-tint`（明 / 暗各一档），需实机验证 WXSS 吃不吃「rgba 里带变量」；不吃则退回固定 alpha。
- `color` 解析：只保证 hex / rgb 可解析并派生浅底；解析不了（`var()` / 色名）时浅底退回 `--mptk-surface-2`，边与字仍用原色 —— 写进 api 文档。
- loading：`loadingMode` = `auto`（默认）/ `inline` / `circle`；auto 判据 = `block` 或显式 `width` 视为定宽走 inline，否则 circle。`circle` = 文字 `visibility:hidden` 占位 + 圈绝对居中，宽度绝对不变；`inline` = 文字前插圈，允许变宽（消费方自选）。传 `loadingText` 时按文案替换并走 inline。
- 圈径：Loader 五档（20/22/24/28/36）与按钮五档字号 1.6 倍正好对齐，不改 Loader。
- 禁用态：现有 `.mptk-btn--disabled` 把品牌色涂成 `--mptk-fg-4` 的糙做法改掉，统一走 `opacity: var(--mptk-opacity-busy)`。
- 按压态：小程序无 hover，按 Cell / Card 的既有做法走 `hoverClass`（`src/ui/display/cell/Cell.tsx:72`、`src/ui/card/Card.tsx:87`），按压只降透明度，不做颜色混算。

**第二轮复验（2026-11-15，loading 三个毛病）**

用户截图反馈：圈在从左上往右下漂、带图标时圈比图标大、圈不转。

- 漂移与「不转」是同一个根因：`.mptk-btn__spinner--center` 用静态 `transform: translate(-50%, -50%)` 居中，而 `.mptk-spinner--circular` 带 `animation: mptk-spinner-rotate`，动画帧的 `transform` 覆盖静态位移 —— 圈的位置从「居中」变成「左上角对齐按钮中心」（视觉偏右下），旋转叠在上面就成了「在飘」。修法：circle 模式套一层铺满按钮的 `.mptk-btn__spin-layer`（absolute inset 0 + flex 居中），圈自己的 transform 只负责旋转；`spinner--center` 规则与类名一并删除。产物已核：`common.wxss` 有 `.mptk-btn__spin-layer{position:absolute;…display:flex;align-items:center;justify-content:center}`，`spinner--center` 在 wxss / js 里均为 0 处。
- 圈比图标大：之前按 `SPINNER_PX` 给 16/18/20/22 px，而字体图标是 1em（12~17px）。改成固定 `1em` —— 与图标同尺寸、随字号档自动缩放，组件里不再维护第二份 px 表。为此给 `Spinner` 的 `size` 扩成 `number | string`（数字按 px，字符串原样），`Loader` 传数字的行为不变。
- 验证动画链完整：`--mptk-s-rotate-full: rotate(360deg)`、`--mptk-c-spinner-rotate-dur: .8s`、`--mptk-s-linear/infinite`、`--mptk-c-spinner-mask: url(data:image/svg+xml…)` 在 `demo/dist/app-origin.wxss` 里都有值。

**第三轮：loading 不转的真因（2026-11-15）**

- 根因不是 Button，是全库关键帧的写法：`@keyframes` 里写了 `var()`（`transform: var(--mptk-s-rotate-full)`）。WXSS 在编译期把关键帧固化成静态表，带 `var()` 的声明**整条丢弃**，动画既不报错也不生效，元素停在初始态 —— 圈看上去就是一圈静止的弧。同一个病还在 `mptk-fb-loader-blink`（Loader 三块脉动）、`mptk-control-breathe`（Segmented 等待态）。
- 修法：这些关键帧的数值全部改字面量（`rotate(360deg)` / `scale(1)` / `scale(.4)` / `opacity: .25` / `.2`），取值与 `kit.config.mjs` 同名项一一对应；`animation` 简写全部拆成长写，只让 `duration` 保留 `var()`（普通属性值不受 keyframes 那条限制）。字面量的漂移由新增断言：「关键帧里不许出现 var()」+ 既有 spinner 断言兜住。
- 例外：`mptk-thumb-breathe` 的底色是每实例算出来的（`--mptk-control-thumb`），无法字面量化，保留 `var()` 并在源码注明「Skyline 下这条不动，由 Switch 的转圈兜底」。
- 产物已核：`common.wxss` 里 `@keyframes mptk-spinner-rotate{to{transform:rotate(360deg)}}`、`.mptk-spinner--circular{animation-name:mptk-spinner-rotate;animation-duration:var(--mptk-c-spinner-rotate-dur);animation-timing-function:linear;animation-iteration-count:infinite}`。
- 长期结论写进 `docs/dependencies/skyline-rendering.md` 的「限制 / 坑」。
- 字号口径：用户问的「首页 cell 左边那个字号」= `.mptk-cell__title` 的 `--mptk-font-sm` = 28rpx = 14px（`src/ui/display/cell/style/index.scss:150-153`）。Button md 上一轮已改成同一个 `--mptk-font-sm`，即两者现在同字号；若视觉上仍显大，来源是白字压深底 + 4px 小圆角，不是字号。
