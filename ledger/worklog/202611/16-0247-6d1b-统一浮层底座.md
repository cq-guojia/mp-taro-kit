**块底两倍间距复发并定案（2026-11-16，第七轮）**

- 现象：上一轮的负外边距方案实机又退回「底部一档变两档」。
- 根因：`calc(0px - var(--mptk-space-3))`（以及更早的 `calc(var(--mptk-space-3) * -1)`）这类负外边距在 Skyline 下被丢弃，规则形同不存在，底部回到卡片 padding 12 + 末项 margin 12 = 24。前几轮在 `:last-child` / 相邻兄弟选择器上兜圈，本质是同一条死路。
- 定案：不再用任何「扣掉一档」的方案。卡片壳 `padding-bottom` 归零，块底那一档只由内容末项自己给：按钮行 / 堆叠末项靠 `.demo-item` 的下外边距，文字收尾靠 `.demo-note` 的 `display: block` + 下外边距（小程序的 `text` 是 inline，垂直 margin 不生效）。浮层显隐与 DOM 兄弟关系都不参与判断。
- 责任判定：不是 Button、不是 Card，是演示站自己的块尾样式（前几轮的负外边距方案）。
- 断言：`tests/ui.test.mjs` 改成核对「壳 padding 归零 + 末项 margin 保留 + note 块级」，并把负外边距、`:last-child`、`+ *`、calc 乘法四种写法列为 `doesNotMatch`。
- 门禁：159/159、build 303、guard、demo build、codelint、docwriter。产物核对：`app-origin.wxss` 为 `.demo-block:not(.demo-block--bare){padding-bottom:var(--mptk-s-zero)}`、`.demo-item{margin-right/margin-bottom:var(--mptk-space-3)}`、`.demo-note{display:block;…margin-bottom:var(--mptk-space-3)}`，四种禁用写法均 0 次。

**间距结构性定案（2026-11-16，第八轮）**

- 用户质疑上一版是打补丁并追问 WebView 安全性 —— 确实如此：上一版靠「Card padding 归零 + 内容末项顶上」，依赖「每个块最后一项都恰好带尾距」这个没写进结构的假设。
- 定案：间距只有一个来源 —— 纵向容器 `.demo-stack` 的相邻兄弟 `margin-top`；`.demo-item` 只带右距、无垂直外边距；多按钮组在页面里显式拆成多个 `.demo-row` 再用 stack 串成多行（actions 的 SIZES / RADII、form 的 5 档 Switch 已拆）。
- 又一处实测坑：写成 `.demo-stack > * + *` 会被 wxss 丢弃（通配符不支持），产物里整条规则消失；改为显式列出 `> view/text/scroll-view/button:not(:first-child)`，产物核对规则已在。
- 块底回到 Card 自己的 `padding-bottom`，demo 不再覆盖库组件内边距；块底与行距不再叠加，也不受浮层显隐影响。
- 五类禁用写法：gap、负外边距、`:last-child` 收尾、通配符选择器、calc 乘法；断言同步重写。
- 双端安全性：只使用 flex、margin、padding、类选择器与标签选择器，全是 WebView / Skyline 共有的基础能力，无平台差异属性。
- 门禁：159/159、build 303、guard、demo build、codelint、docwriter。产物核对：`.demo-item{margin-right:var(--mptk-space-3)}`（无 margin-bottom）、`.demo-note{…}`（无 margin-bottom）、`.demo-stack>view:not(:first-child),…{margin-top:var(--mptk-space-3)}`。

**风险（未验证，留给实机）**

- Skyline 下 `ScrollView` 放在 `position: fixed` 面板内能否内滚；不行就退成「限高 + 内容裁剪」或由消费方自己接滚动容器。
- `catchMove` 拦得住页面原生滚动，但拦不住消费方 `scroll-view` 容器的滚动，需要那边在浮层打开时关 `scroll-y`；这条已写进 `docs/api/overlay.md` 的边界，不假装能全锁。
- 数字浓度走内联 CSS 变量 `--mptk-overlay-alpha`，若 Skyline 不支持内联自定义属性，数字档会退回默认浓度（降级不影响功能）。
