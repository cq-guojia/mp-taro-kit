### 结论

用「命名空间注册表 + id 直映射路径」：一条配置 = 一个平台项目，`id` 用用户给的点号全名；点号直接映射目录层级，`./ui/*` 通配出口不变；`visibility` 决定落盘位置与发布面；类名一律从平台 CSS 解析并校验。以后加 `common.social` / `common.office` 只加一条记录，不改生成器、不改 `package.json`。

### 判据

| 点 | 做法 | 依据 |
|---|---|---|
| 名字只有一处真源 | 注册表 `id` 同时决定目录、出口路径、文档称呼，不再有 `base` / `base-color` / `mptk-icons-base` / `koc-i-common-base` 四套叫法 | `scripts/icons.mjs:16-31`、`docs/api/icons.md:11-18` |

| 对外边界一个字段 | `visibility: public \| demo` 统一决定落 `src/` 还是 `demo/`、是否生成 `names.ts` / `index.ts`、是否写进对外文档 | 现在靠 `dest` + `styleOnly` 两个隐含约定（`scripts/icons.mjs:19-30,86-90`）；`package.json:7-10` 已保证 demo 不进 npm 包 |
| 生成期自检代替人肉核对 | 校验 `id` 带 `.color` ⇔ CSS 含 `/* Color fonts */`、基础类 = `@font-face` 的 font-family、图标类前缀 = 基础类加 `-`、public 包在 dist 有产物、demo 包不在 dist；不符即拒绝写出 | `scripts/lib/icons-parse.mjs:14-47` 有解析能力，缺的是匹配校验 |
| 类名不重写 | font-family、前缀、图标名全部读 CSS，生成器不推导 | `docs/api/icons.md:30`：改平台设置即等于改对外类名 |
