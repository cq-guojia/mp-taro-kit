## Background

2026-11-12 用户在图标分包讨论中提出：单色图标靠 `currentColor` 自动跟随明暗就够了；彩色图标颜色固化在 CPAL 调色板里改不了，需要「深色用 A 图标、浅色用 B 图标」，并希望调用方不用管。

前置实测与结论：

- `content: var(--mptk-i-x, "\e61c")` 在真机 Skyline 下生效，变量能把字形换掉（demo「图标 → 换字形能力验证」C 格由 home 变 logo）。
- `theme-auto` 是纯 CSS 媒体查询（`src/design/theme-auto.scss:9`），JS 读不到当前生效的是哪一套 → 运行时「自动选版」不可行。
- 因此走 CSS 变量 + 覆盖关系：有定义用变体、没定义回落默认，不写任何查找逻辑、不引入运行时主题状态。

## Process

- 真机实测（2026-11-12）：`content` 吃 CSS 变量、变量可换字形。探针在 `demo/src/app.scss` 的 `.demo-probe-a/b/c`，产物见 `demo/dist/app-origin.wxss`。
- `base` 已换单色项目 `5251349_5n3d5h8pvsn`，远程解析 ttf 无 `COLR` 表，`numGlyphs=10`（9 图标 + notdef）。
- 彩色判定读平台 CSS 的 `/* Color fonts */`，粒度是整包，不是单个图标。
- 平台「彩色」是项目级导出选项，勾了会把单色线稿也包成 COLR 字形，所以彩色/单色必须分项目。

## Conclusion

机制与工具链已落地，产物零变化（当前所有包都没有 `-dark` 图标）：

- `scripts/lib/icons-parse.mjs`：`parseIcons` / `renderVariantScss` 两个纯函数，不联网不落盘。
- `scripts/icons.mjs`：改用纯函数；有配对才写 `style/dark.scss` 与 `style/auto.scss`；`names.ts` 出 `iconPaired`。
- 覆盖形态：基础样式零改动，`dark/auto` 只写有变体那几条（`page .mptk-i-<名>:before { content: "<暗色码位>" }`），没变体的图标明暗共用同一字形。
- 放弃 `content: var()` + 变量兜底：它依赖 `page` 变量被后代 `:before` 继承，Skyline 未验，失败会让变体图标整体消失。纯覆盖无此依赖。
- `tests/icons.test.mjs`：8 项断言全过（配对识别、变体不进 `iconNames`、占位过滤、混合场景只覆盖有变体的、两套渲染、无配对返回 null）。

未完成：真机验证暗色字形切换（缺真实 `-dark` 图标）；`prefers-color-scheme` 在 Skyline 下未验证，`auto.scss` 的正确性依赖它。
