**本轮实现定案（2026-11-19）**：

- 拆两层：`FloatingActionGroup`（一个 fixed 列，管 position 档 / 安全区 / 多实例竖排 / 层级）+ `FloatingAction`（按钮本体，复用核心 Button 的内容轴与四轴外观，只加受控 `visible` + `usePresence` 进出场）。单个按钮自己做 fixed 会互相重叠，所以两层是硬约束。
- 落点：`src/ui/layout/floating-action/{FloatingAction.tsx,index.ts,style/index.scss}`；组件级与 layout 子域 barrel 双出口。
- CSS 关键：列容器 `z-index: var(--mptk-c-layer-navbar)`；退场期 `pointer-events: none`；竖排用相邻兄弟 `margin-top` 不用 gap；贴底档叠 `env(safe-area-inset-bottom)`。

**用户反馈后的返工（2026-11-19 第二轮）**：

- 用户反馈演示站菜单没看到 → 菜单名从占位的「Layout 布局」改成「FloatingAction 浮动按钮」（id/pageId 仍 layout）。
- 用户反馈界面丑、点按钮全体消失、要四档位置 / 半透明底 / 大圆角偏大尺寸 / 真实图标。逐条修：
  - 演示页按 popup 的配置式重做：CellGroup + Segmented 配位置 / 显隐，三图标 `shezhi` / `huidingbu` / `xiugai`。「点按钮全消失」是 **demo 逻辑错误**（旧 demo 把每个按钮 onClick 写成 `setVisible(false)`），不是组件问题；改为点按钮只回执点击，显隐只由 Segmented 控。
  - 位置两档扩四档：`bottom-right` / `right-middle` / `bottom-left` / `left-middle`，默认右下；安全区只对贴底两档。
  - 默认外观进组件与 token（不是只在 demo 传参）：`size='lg'`、`radius='xl'`（大圆角非正圆）、半透明底 `--mptk-c-fab-bg` 放 light/dark 语义段各一份（明 rgba(59,91,219,.78) / 暗 rgba(107,138,253,.78)）；CSS 只覆盖 `--mptk-btn-bg`、字色描边不动，传 `color` 时行内盖过。
  - 踩坑：`component` 段是明暗共用一份、不分段，最初把两个同名 `--mptk-c-fab-bg` 塞进去被 codelint 判重复键；移到 light/dark 语义段后修复。
- gate：`pnpm run build`（335）→ `pnpm test`（182/182）→ `pnpm run guard` → demo build:weapp → codelint 20 文件，全过。已核对 `demo/dist/pages/layout/index.wxss`（四档类名 + 半透明底覆盖规则）、`common.js`（三图标、CellGroup/Segmented）、`app-origin.wxss`（明暗两份 token 值）、库产物 `dist/ui/layout/floating-action/FloatingAction.js`（`size='sm', translucent=true`）。

**用户反馈后的第三轮调整（2026-11-19）**：

- 演示页去分组标题、去底部说明；配置 cell 从 2 个扩到 7 个：位置 / 显隐 / 大小 / 描边 / 圆角 / 底色 / 背景。
- 用户明确按钮尺寸太大、要对齐 Button → 组件不再强设 `size`（回归 Button 默认 `sm`）与 `radius`（继承 Button），描边 / 底色类型 / 尺寸 / 圆角全走 Button 原生轴 `variant` / `type` / `size` / `radius`，组件不另造。圆角演示三档：纯圆 `pill` / 大 `xl` / 中 `md`。
- 半透明底拆成独立 prop `translucent`（默认 true）：只在 `variant='solid'` 时覆盖 `--mptk-btn-bg`，描边档 / 字色 / 其它形态让位给 Button；传 `color` 自定义色两档都让位。原因：上一轮无条件覆盖把 `type` / `variant` 全盖掉，导致「用哪个底色 / 带不带描边」根本不生效。
- 演示页「背景」开关切 `translucent`；底色切 `type`；描边切 `variant`。
- gate 全过，已核对 `demo/dist/pages/layout/index.js` 七个配置标题（unicode 转义）、圆角三档与描边两档选项、半透明规则只覆盖实心档、库产物默认值 `size='sm' / translucent=true`。

**用户反馈后的第四轮调整（2026-11-19）**：

- 用户确认「底色 / 描边均能传颜色」走 Button 的 `color` 一个口子（派生底 / 边 / 字三段，支持 token 与字面色值），组件不另造两个颜色 prop；去掉演示页「底色」语义色 cell（`品牌/成功/警告/危险` 不拿来命名底色），默认用 Button 默认，要换色自己传 `color`。
- 默认值定为：`size='sm'`、`variant='outline'`（带描边）、`radius='md'`（中圆角）、`translucent=true`；圆角演示加小档（`sm`），共 纯圆 / 大 / 中 / 小 四档。演示页 cell 回到 6 个：位置 / 显隐 / 大小 / 描边 / 圆角 / 背景。
- 半透明覆盖扩到 `solid` 与 `outline` 两档的 `--mptk-btn-bg`（描边变量 `--mptk-btn-border` 不动），让「带描边 + 半透明底」同时成立——上一轮只覆盖 solid 时默认 outline 会变白底、半透明失效。
- gate 全过，已核对库产物默认值 `sm/outline/md/translucent`、演示站 wxss 中半透明覆盖两档底色、`index.js` 六个配置标题与圆角四档。

**用户反馈后的第五轮调整（2026-11-19）**：

- 用户明确「次要按钮不该用亮品牌蓝，要用刚才那种灰」。两处一起改，只改 type 不够（半透明 token 还是蓝的会把底盖回蓝）：
  - 组件默认 `type='default'`（盖过 Button 自带的 `primary`），描边 / 字色随之走中性灰。
  - `--mptk-c-fab-bg` 从写死的品牌蓝 rgba 改为 `var(--mptk-default-soft)`（明 `gray-1` / 暗 `gray-3`），明暗自适应、不抢眼，与 Button 默认灰同源。
- 教训：默认色要跟随库既有语义灰，别为浮层单独调亮色 rgba——次要入口的视觉权重由 type 与 token 共同决定，只改一头没用。
- gate 全过，已核对库产物 `type='default'`、产物中 fab-bg→default-soft 两份（明 gray-1 / 暗 gray-3）、亮蓝 rgba 无残留。
- 注意：演示页样式必须显式引组件级出口 `mp-taro-kit/ui/layout/floating-action/style`，子域 `layout/style` 不转发它。

**能力边界讨论结论（2026-11-20）**：

- 用户提三类功能：滚动阈值呼出（回顶 / 100~200 才出 icon）、状态变化（点击后变色 / 换图标 + 小动画）、条件获取。组织三方专家论证 + 参照 Ant Design FloatButton（`visibilityHeight` 阈值 + `FloatButton.BackTop`）、TDesign Fab（`button-props` 透传），结论一致——**壳已够，库零改动、不加 active 轴、不加 inRange 工具函数**：
  - 条件→布尔：消费方原生比较（`top > 300` / `top > 100 && top < 200`），一行搞定，区间判断不值得进 utils。
  - 布尔→显隐：`visible` + `usePresence` 已支持。
  - 状态变化：改透传的 `type`/`color`/`icon`/`glyph` 重渲染，动画挂 className 只动 opacity/transform。
  - 不进库：滚动监听（库拿不到消费方 scroll-view）、active 语义轴（业务语义不统一，现有 props 够）、区间工具函数（一行比较不值得）、回顶业务组件（归 75c1）。
- 这条结论已写进 `docs/api/floating-action.md`「条件触发怎么写」。
