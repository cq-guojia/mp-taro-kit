代码核查（已读，根因定位）：

- **形状档无效根因**：`resolveCloseStyle()`（`src/ui/layout/close-style.ts:20-29`）实际输出只有 `variant` + `radius`，且 `rounded` 映射的是 `radius: 'md'` = 12px（`kit.config.mjs:65`）；按钮是 **icon-only 正方形**（`actions/style/index.scss:166-171`：宽高都锁 `--mptk-btn-h`），xs 档 24px。24px 方块 + 12px 圆角 = 视觉上接近正圆，所以 `circle`（pill）和 `rounded`（md）看起来一样。要分开得让 rounded 用更小的圆角档（如 `--mptk-radius-xs` 4px / `sm` 8px），或给关闭按钮单独的圆角变量。
- **按钮尺寸**：`Popup.tsx:137` 写死 `size="xs"`（24px）。要「圆加大、叉不变」只能拆成两个变量：外框尺寸（改 `--mptk-btn-h` 或加 popup 私有 close-size）与图标字号（`--mptk-btn-font`，xs 档 12px）——`Button` 的 icon-only 宽高都跟着 `--mptk-btn-h` 走（`actions/style/index.scss:168-171`），只调字号不会放大外框。
- **半跨左右距**：`.mptk-popup__close--edge-top-left/right`（`layout/style/index.scss:237-247`）左右都是 `var(--mptk-space-2)` = 8px（`kit.config.mjs:79`）；1.5 倍 = 12px = `--mptk-space-3`（`kit.config.mjs:80`）。用户说「半跨只有上 / 下边」对应 `edge-top-left/right` 只挂在 `panel--bottom` 与 `panel--center`（`close-position.ts:25-28`）。
- **让位误伤 center/bottom 根因**：`Popup.tsx:93` 是 `insetTop ?? (isTopAnchored(position) ? 'nav-bar' : 'none')`——**不传**时确实按位置判定（center/bottom = none）；但 demo 的 `shared` **显式传了** `insetTop`（`demo/src/pages/popup/index.tsx`），于是 `??` 左侧命中，center/bottom 也被让位。修法：判定顺序反过来，先按 `isTopAnchored(position)` 决定**是否允许**让位，不允许时无论传什么都取 `none`；`resolveTopInset` / `safe-inset.ts` 本身不用改。另外 popup 根节点 `names` 里 `mptk-popup--inset-*` class 也要跟着这个判定走，否则 CSS 兜底照样加 padding（`layout/style/index.scss:75-89`）。

2. **描边与叉不是同一色**——查明属实：核心 Button 的 `default` soft 档描边取 `--mptk-gray-5`（明色 #c8c9cc）、叉取 `--mptk-fg-2`→`ink-2`（#5c6370），两 token 解析后不同色；用户觉得「叉更白」是细笔画 + `-webkit-font-smoothing: antialiased` 的视觉假象，字色其实更深。按用户「不同色就调成同一色」授权，让描边跟随叉色：`layout/style/index.scss` 加三类名规则 `.mptk-btn.mptk-popup__close.mptk-btn--soft { --mptk-btn-border: var(--mptk-btn-fg) }`，压过双类名 default soft，与库内 tone 档 soft 的 fg/border 同色约定一致，只作用于 popup 关闭按钮。`tests/layout.test.mjs` 断言根因（两 token 不同色）+ 归一规则，`docs/api/overlay.md` 同步并记下偏上根因。
