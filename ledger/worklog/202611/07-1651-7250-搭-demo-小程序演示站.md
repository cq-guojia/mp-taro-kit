## Process

npm 最新版本实测（`pnpm view`）：react / react-dom 19.3.1、@tarojs/* 4.3.2、@types/react 19.3.0、typescript 7.0.2。

例外：typescript 不用 7.0.2。`scripts/build.mjs` 依赖 `ts.createProgram().emit()` 两遍编译，TS 7 是 native 编译器、没有该 API；`docs/dependencies/compiler-toolchain.md` 已记此约束。demo 的 devDependencies 与主库同用 ^5.9.3，避免 workspace 里出现两个 TS 版本。这是保护本库构建，不是迁就老项目。

React 19 与本库 peer 下限 >=18 不冲突；根 devDependency `@types/react@^18.3.31` 只服务本库编译期，demo 单装 `@types/react@^19.3.0`，正好用来验证 `docs/dependencies/compiler-toolchain.md` 里「React 19 类型下 import("react").JSX.Element 能否解析」这条未验证假设。

`pnpm-workspace.yaml` 加 `packages: ['demo']` 后，根包仍是 workspace root；`autoInstallPeers: false` 保留，peer 不自动装、由 demo 显式提供。

Taro 4 入口约定（源码级核实）：`@tarojs/helper/dist/utils.js:630` 的 readConfig 用 `esbuild.buildSync({ bundle: true })` 求值配置，所以 `app.config.ts` 从 catalog 动态派生 pages 可行；实测 `demo/dist/app.json` 有 9 页且 `renderer: "skyline"`。`vite-runner/dist/utils/compiler/base.js:144` 的 getConfigFilePath 按 app 入口同名取 `.config`，`sourceRoot: 'src'` 要求 `src/app.config.ts` 存在，故保留根 `app.config.ts` 为真源、在 src 下加一行转发。

pnpm workspace 隔离：`vite-runner/dist/mini/config.js:268` 把 `@tarojs/components` 换成 `@tarojs/plugin-platform-weapp/dist/components-react` 裸包名，而主库 `dist/` 位于工作区根、不在 demo 的 node_modules 树下，构建报 ENOENT。给根 package.json 加 devDependency 会得到 pnpm 断链（store 只有带 peer 后缀的实例），改用 `pnpm-workspace.yaml` 的 `publicHoistPattern` 公开提升该插件后从库根可解析、build 通过；约束已写进 `docs/architecture/demo-mapping.md`。

`autoInstallPeers: false` 下 Taro Vite 链的 peer 不自动装，补了 vite ^4.5.14 / postcss / @vitejs/plugin-react / sass / @babel/preset-react 等编译期依赖；vite 受 `@tarojs/vite-runner` 的 `vite: ^4` peer 约束，不用 7。install 报 React 19 与 Taro 类型 peer ^18 不匹配，属已知上游风险，未阻塞构建。

两个待验点已有结论：动态派生 pages 被识别（app.json 9 页）；React 19 类型下主库 `.d.ts` 可解析（`tsc --noEmit` 零诊断，期间修了 `Taro.scanCode({})` 参数与 tsconfig target es2020 以支持 flatMap）。这是类型层结论，不是实机验证。
