# 设计基础

本库的视觉取值只有一个真源：`src/design/_tokens.scss`。本篇解释这套取值怎么分档、明暗怎么对应、组件与演示站该怎么消费；出口形态与引用方式见[对外契约](../api/exports.md)，效果展示分归 `demo/` 的设计基础页与尺寸页，两件事各成一页。

## 1. 为什么单独成篇

[架构总览](overview.md) 只写系统组成与依赖方向，[演示站映射](demo-mapping.md) 只写页面与菜单怎么分组，都不承载取值依据。颜色、明暗与尺寸是可变且会被反复追问的一组事实，需要一篇长期结论；组件文档只指向本篇，不复制取值。

## 2. 真源

样式真源是 `src/design/_tokens.scss` 的 `base` / `surface` / `light` / `dark` 四个 mixin。`base` 放不随明暗变化的档位，`surface` 只声明页面底色，`light` 与 `dark` 放颜色。四份主题入口各自 `@include` 其中几个 mixin，编译出 `dist/styles/` 下的主题产物；改一处四份一起变，产物不许手改。

`base` 与 `light` / `dark` 的边界是「是否随明暗变化」：控件高度、字号行高、间距、圆角、动效时长只在 `base` 写一次；颜色一律在 `light` / `dark` 各写一份。

## 3. 颜色

### 3.1 中性灰阶

八档 `--mptk-gray-1` 至 `--mptk-gray-8`。编号表示**层级**，1 是最底层、8 是最上层文字；明色下 1 最浅 8 最深，暗色下方向相反。组件取同一编号就拿到当前主题下该层的色，不需要按主题改类名。

`--mptk-surface-*` 与 `--mptk-fg-*` 是这套灰阶的语义别名。明色下卡片仍为纯白，页面底色走浅灰（`gray-2`），次级面比页面浅一档（`gray-1`），下沉面与滑轨同档；暗色页面底色取深灰而不是纯黑。页面底色与官方窗口主题配置的 `bgColor` 一致，不许两处漂移。

纯白与文字三档同样在色板里有名字，不裸写色值：`white`，以及文字专用的 `ink-1` / `ink-2` / `ink-3`（明暗各一套值）。`--mptk-surface-1`（明色）、`--mptk-fg` / `fg-2` / `fg-4` 都引用它们。所以「卡片面」在明色是 `white`、暗色是 `gray-2`，配置时写的是名字而不是色值。

边框三档 `--mptk-border-faint` / `--mptk-border` / `--mptk-border-strong` 之外，`--mptk-cell-divider` 是 Cell 组内分隔线的语义键，默认比外框的 `--mptk-border` 浅一档（明暗各 `.06`）。控件级切换由 `CellGroup` 的 `dividerTone` 等 props 派生修饰类完成，宿主也可在业务级主题定制时覆盖同名变量；组件只引用变量、不写兜底。新增颜色键仍须明暗同名同数。

`--mptk-card-bg` / `--mptk-card-border` 是卡片面与描边的语义键，`light` / `dark` 同名同数；`--mptk-card-radius`（默认指向 `--mptk-radius-md`，与控件圆角同档）与 `--mptk-card-spacing` 是不随明暗变化的基线量，只写在 `base`。`--mptk-card-spacing` 只决定普通内容的留白：内容是贴边组件时由 `Card` 派生 `--edge-content` 直接归零，不再把这支变量交给子级抵消。容器不引用 `--mptk-control-radius`：那支是给 Button / Segmented 的控件圆角。`Card` 的 `radius` / `size` / `color` 都是枚举或色值输入，组件派生修饰类换档，宿主不查变量名单、不写样式，见 [Card 卡片](../api/card.md)。

### 3.2 色相

八支基础色相：蓝、绿、橙、红、紫、青、粉、蓝绿。每支四档：

| 档 | 变量名后缀 | 用途 |
|---|---|---|
| 本色 | 无 | 实面、选中态、强调文字 |
| 悬停 | `-hover` | 指针停留 |
| 按下 | `-active` | 按压反馈 |
| 浅底 | `-soft` | 同色系极淡底，状态标签与提示块 |

明色下按压往深走、暗色下往亮走；浅底浓度明色 8%、暗色 12%。派生值一律落成具体色值：小程序 WXSS 不保证支持运行时混色，算不出来会让整条声明作废。

### 3.3 语义色与控件主色轴

`--mptk-business` / `success` / `warning` / `danger` 是给宿主用的语义别名，`--mptk-control-*` 是控件内部用的主色轴，两者引用同一组色板值。分开的原因是宿主定制业务色不该把开关染成自己的品牌色；主色轴默认指向蓝，内置蓝绿橙红四色、也接受任意 CSS 色值；其中 Switch 把默认值覆盖成绿，对齐微信原生开关，见 [Switch 开关](../api/switch.md) 与 [Segmented 分段选择](../api/segmented.md)。

等待态有两种表达：转圈（只给没有被内容占住的控件，如 `Loader` 的 `ring`、`Loading`、光板 `Switch`）与底色呼吸（内容位已被占住时用，如 `Segmented`、带图标 / 文字的 `Switch`）。呼吸只加在选中那块滑块上，轨道整块与文字不跟着闪，也不加节点、不挤宽；周期取 `--mptk-dur-breathe`（1120ms，一次 1.6s 的等待里约一次半起伏；更快会变成闪烁），两支关键帧同在真源 `src/ui/form/_busy.scss`。彩色滑块（`Segmented`）走 `mptk-control-breathe` 的 `opacity 1 → .2 → 1`；白滑块（`Switch`）不能靠透明度 —— 明色下内衬也是白的，白再淡也还是白 —— 改走 `mptk-thumb-breathe`，在 `--mptk-control-thumb` 与 `--mptk-control-thumb-dim` 之间灰白换色。后者是明暗各给一支的语义键（明色 `gray-5`、暗色 `gray-8`），都取偏浅的中性灰，保证滑块上的深色文字仍有对比。

自绘转圈只占一个键：`--mptk-spinner-active` 是圆环与追逐点的主色，明暗各给一套。`Spinner` 有两种形态，几何都取自成熟开源实现、只把颜色换成主题变量：默认 `circular` 是 TDesign 小程序 `t-loading theme="circular"` 的圆锥渐变弧 + 环形遮罩挖空，`chase` 是 SpinKit `sk-chase` 的六点追逐。两者都不给单边边框上色：Skyline 下单边边框上色会让圆角整个失效，圆环会退化成旋转的方框。颜色统一走 `currentColor`：容器默认挂 `--mptk-spinner-active`，圆环、追逐点、`Loader` 的 blocks 三种形态同色；`Loader` / `Spinner` / `Loading` 的 `color` 内联覆盖它 —— 不复用业务色，也不跟宿主品牌色跑。圆环粗细照 TDesign 实测比例：其 `radial-gradient` 遮罩默认 `farthest-corner`，环带约占直径 17%。

### 3.4 明暗对应

编译期三选一由 `page` 上的变量决定，运行时热切换由 `.mptk-dark` 覆盖同一组颜色键。运行时产物另给 `.mptk-light`：只覆盖明色键，套在任意容器上即可把该子树强制回明色，用于同一屏并排展示明暗两套取值（演示站「主题配置」页就靠它）。两个标记都只覆盖颜色键，基线仍从 `page` 继承。组件只写 `var(--mptk-*)`，不感知主题、不自带兜底色值。

暗色不是把明色数值取反：色相整体提亮、按压方向反转、浅底浓度单独给，两条曲线由 `light` / `dark` 各自维护。所以颜色键必须同名同数，新增颜色要同时给两档。

### 3.5 站点级覆盖

总配置只有一份，站点把它当默认值用，要改哪条就覆盖同名变量：明色落 `page`、暗色落 `.mptk-dark`（运行时出口）或媒体查询内（跟随系统出口），颜色必须两套一起给。覆盖只写要改的键，其余继续吃默认值，组件与演示站都不改代码。可覆盖的主要是页面底色、卡片面与描边、四个语义色、控件主色轴、控件圆角与三档高度；模板见 `demo/src/app-theme.scss`（演示站沿用默认值，整份注释着，改哪条取消哪条）。演示站「主题配置」页按基础配置 / 颜色配置 / 其他控件配置三张卡片列出默认值：颜色一列明一列暗，色条上写的就是设计基础里的名字（`gray-2`、`white`、`ink-1`、`blue` 等），并给出这份覆盖写法的片段。

## 4. 尺寸

### 4.1 控件高度

三档 `--mptk-control-h-sm` / `-md` / `-lg`，取值 32 / 40 / 48，与 WeUI 2.6.x 的按钮高度三档一致，默认 `md`（40）。承载文字的控件用 `size="sm|md|lg"` 选档；总高必须逐像素等于该档，不许由上下内边距撑出来，调用点也不自定义高度。真不够用才在调用点覆盖同名变量，属例外。

不传 `size` 时取 `CONTROL_SIZE_DEFAULT`（`mp-taro-kit/design` 导出，当前为 `md`）。Button / Switch / Segmented 共用这一个默认值，输入类控件落地后同样引用，不各写一次；宿主逐实例改默认值就传 `size`。

### 4.2 其余档位

| 组 | 档位 | 取值 |
|---|---|---|
| 字号 / 行高 | xs / sm / md / lg / xl | 12/17、14/20、15/22、17/24、22/30 |
| 图标 | xs / sm / md / lg / xl / nav | 直接取上面的字号档，不另立图标像素表 |
| 加载圈 | xs / sm / md / lg / xl | 20 / 22 / 24 / 28 / 36（字号 × 1.6） |
| 间距 | space-1 至 space-4 | 4 / 8 / 12 / 16 |
| 圆角 | xs / sm / md / lg / xl / pill | 4 / 8 / 12 / 16 / 20 / 全圆 |
| 动效 | dur-fast / dur / dur-run | .12s / .2s / 500ms |

字号档位与《微信小程序设计指南》5.1 的常用字号对应；宿主不整体覆盖档位，需要强调时用组件已有的语义位，不新增字号。

图标与文字共用这一套：字体图标本身继承所在文字字号，`Icon` 的 `size` 档位只是把这套字号档显式选出来，所以系统里只有一张尺寸表。加载圈是唯一的派生档，比例（字号 × 1.6）取自 TDesign 圈径与文案的字号比。

## 5. 不可破的约束

- **取值只写一次**：颜色与尺寸值只在 `src/design/_tokens.scss` 出现；组件 CSS、演示站样式与文档都不复制色值，演示站色板直接读 `var(--mptk-*)`。
- **组件只写变量、不写兜底**：组件样式禁止硬编码颜色，也禁止 `var(--mptk-x, #fff)` 形式的兜底；没引样式基线时取不到值属于接入错误，不是组件该掩盖的情况。
- **明暗两套键同名同数**：`light` 与 `dark` 的颜色键一一对应，新增颜色必须同时给两档，否则热切换会露出色值断层。
- **页面底色与官方窗口配置一致**：`--mptk-surface-base` 的明暗值与 `theme.json` 的 `bgColor` 两档相同，`tests/theme.test.mjs` 会核对。
- **层级编号不按明度理解**：`--mptk-gray-*` 的编号是层级，明暗方向相反；不许写死「gray-8 是深色」这类判断。
- **派生色不用运行时混色**：小程序 WXSS 不保证支持 `color-mix` 与相对颜色语法，派生值必须落成具体色值。
